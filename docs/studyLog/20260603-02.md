# 2026-06-03

## 소스코드를 뜯다가 잡은 내 실수 하나

오늘 장바구니 화면을 테스트하다가 이상한 점을 발견했다. 체크박스가 눌러지질 않았다. 정확히 말하면, 클릭해도 아무것도 일어나지 않았다. 초기 상태가 전체 선택이라 처음에는 체크가 된 것처럼 보였는데, 해제하려고 클릭해도 반응이 없었다.

처음에는 상태 관리 로직을 의심했다. `useCart.ts`의 `toggleItem` 함수를 다시 읽어봤는데 논리적으로 문제가 없었다. `Set.has(id)`이면 `delete`, 없으면 `add`하는 단순한 토글이었다. `CartPage.tsx`에서 `onCheckedChange={() => toggleItem(item.id)}`로 연결된 것도 맞았다. 이 화살표 함수가 SEED Design의 `onCheckedChange(false)`를 받아도 무시하고 `toggleItem`을 호출하는 구조라 인자 문제도 아니었다.

결국 SEED Design의 `Checkbox` primitive 소스코드를 직접 뒤졌다. `@seed-design/react-checkbox/src/Checkbox.tsx`를 열어보니 compound component 구조가 이랬다.

```tsx
export const CheckboxControl = forwardRef<HTMLDivElement, CheckboxControlProps>((props, ref) => {
  const { controlProps } = useCheckboxContext();
  const mergedProps = mergeProps(controlProps, props);
  return <Primitive.div ref={ref} {...mergedProps} />;
});
```

`Checkbox.Control`은 그냥 `div`였다. 체크 표시를 그리는 시각적 요소만 담당하고, 클릭 이벤트 처리는 전혀 하지 않는다.

실제 클릭 핸들러가 들어있는 것은 `Checkbox.HiddenInput`이었다.

```tsx
hiddenInputProps: inputProps({
  type: "checkbox",
  onChange(event) {
    setIsChecked(event.currentTarget.checked);
  },
  ...
}),
```

`Checkbox.Root`는 `<label>` 요소로 렌더링된다. HTML 규칙에서 label의 클릭은 연결된 `<input>`으로 전달된다. `HiddenInput`이 없으면 label은 전달할 input이 없어서 클릭이 그냥 사라진다. 내가 짠 코드는 아래처럼 HiddenInput이 빠져 있었다.

```tsx
<Checkbox.Root checked={checked} onCheckedChange={onCheckedChange}>
  <Checkbox.Control />   {/* div만 있고 input이 없다 */}
</Checkbox.Root>
```

초기 상태가 전체 선택이라 체크된 것처럼 보였지만, 사실 클릭 자체가 아무것도 하지 않았던 것이다. 처음부터 작동하지 않았는데 작동하는 것처럼 보였다.

고치는 건 간단했다.

```tsx
<Checkbox.Root checked={checked} onCheckedChange={onCheckedChange}>
  <Checkbox.HiddenInput />
  <Checkbox.Control />
</Checkbox.Root>
```

이 버그에서 compound component 설계의 의미를 다시 한번 생각하게 됐다. 단일 컴포넌트였다면 내부에서 HiddenInput을 알아서 렌더링했을 것이다. 조각으로 쪼개놓으면 조합이 자유로운 대신, 필요한 조각을 빠뜨리면 아무도 경고해주지 않는다. 자유도와 실수 가능성은 트레이드오프 관계다. 문서를 꼼꼼히 읽거나 소스코드를 직접 들여다봐야 이런 실수를 피할 수 있다.
